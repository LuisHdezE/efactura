# UI-POS-001 — D1.3 Visual Fidelity Implementation

Status: `IMPLEMENTATION_IN_PROGRESS / APPROVED_BASELINE_TARGET`

Approved visual authority:

`documentation/ui/references/approved/UI-POS-001/v3-theme-pair/`

## Objective

Replace the spacious D1.2 presentation with a denser POS composition aligned to the explicitly approved `UI-POS-001 v3-theme-pair`, while preserving the already implemented mock sales lifecycle and current API authority boundaries.

## Implementation scope

- compact desktop shell and POS layout;
- deep navy dark theme and light counterpart;
- operator-visible light/dark toggle;
- local theme persistence through `localStorage`;
- `prefers-color-scheme` used only when no local preference exists;
- approved product sprite copied byte-for-byte into the WebApp public assets;
- product visual mapping remains presentation-only metadata;
- tighter typography, card dimensions, gaps and current-sale rows;
- product/service filters based only on authoritative `kind` already present on `CommercialItemDto`;
- existing create/update draft, validate and fiscal-preview mock lifecycle retained.

## Exact approved asset reuse

The WebApp asset:

`src/WebApp/public/assets/ui-pos-001/v3/product-sprite.webp`

uses the same Git blob as the approved visual package:

`8e0523a24a43bad000d16057cf2404294c4921a0`

No new product imagery is generated by this increment.

## Authority boundaries preserved

This increment does not introduce:

- authoritative catalog selling prices;
- stock quantities;
- browser-authoritative tax calculation;
- automatic CFE selection;
- DGI acceptance claims;
- payment-method discovery;
- cancellation;
- durable confirmation without governed settlement inputs;
- fiscal representation download;
- authoritative offline operation.

The catalog therefore intentionally does not copy the reference mockup's visible prices, because the current `CommercialItemDto` has no authoritative selling-price field. Unit price continues to be captured on the sale line.
